# פרומפט בנייה: "הג'ונגל שלי" — אפליקציית ניהול צמחי בית

## תפקיד ומטרה
אתה מפתח Full-Stack בכיר ומומחה UX בעברית. בנה אפליקציית PWA בעברית מלאה (RTL) לניהול צמחי בית, עם זיהוי צמח מתמונה ואבחון מצב צמח מתמונה ו/או תיאור מילולי, מבוססי Claude Vision.

## אילוצים מחייבים
1. **תיקייה חדשה `plants-app/` בלבד.** אסור לגעת בקבצי BOX הקיימים (`app/`, Gradle, `.github/workflows/build-apk.yml`).
2. **מפתח ה-API של Anthropic נשמר בשרת בלבד** (משתנה סביבה). לעולם לא בקוד הלקוח, ב-git או בלוגים.
3. **כל הטקסטים בעברית**, `dir="rtl"`, פונט עברי קריא. תאריכים ומספרים בפורמט ישראלי.
4. **אין "אימון מודל".** הידע מגיע מ-Claude עם פרומפטים טובים ופלט JSON קבוע, ומתועד בנוסף במאגר ידע מקומי של צמחים נפוצים.
5. אמירה כנה של אי-ודאות: כשהביטחון נמוך, הצג 2–3 אפשרויות ובקש תמונה נוספת. אל תמציא.

## ארכיטקטורה
- **Frontend:** PWA (Vite + TypeScript, ללא ספריות כבדות), manifest ו-service worker, התקנה למסך הבית, העלאה/צילום מהמצלמה (`<input capture>`), כיווץ תמונה בצד לקוח לפני שליחה (עד ~1600px, JPEG).
- **Backend:** Node.js + TypeScript (Fastify), פרוקסי ל-Anthropic API, אימות בקשות, הגבלת קצב, ולידציית קלט (סוג/גודל תמונה).
- **מסד נתונים בענן:** PostgreSQL (Supabase או Neon) + אחסון תמונות. סכמה: `plants`, `photos`, `diagnoses`, `care_tasks`, `growth_entries`. כניסת משתמש באימייל (Supabase Auth או שווה ערך).
- **מודל:** השתמש בסקיל `claude-api` לאימות מזהי מודלים עדכניים, Vision, ופלט מובנה (JSON schema). בחר מודל לפי יחס עלות/דיוק ותעד את הבחירה.

## פיצ'רים (לפי עדיפות)
1. **זיהוי צמח:** תמונה → שם נפוץ בעברית, שם מדעי, ביטחון (0–1), 2–3 חלופות, כרטיס טיפול (אור, השקיה, לחות, טמפרטורה, קרקע, הזנה), כפתור "הוסף לג'ונגל שלי".
2. **המאגר שלי:** רשימה/גריד של צמחים עם כינוי, תמונה, מיקום בבית (סלון/מטבח...), תאריך הוספה, הערות, חיפוש וסינון, עריכה ומחיקה.
3. **אבחון מצב צמח:** תמונה ו/או תיאור חופשי ("העלים מצהיבים והאדמה תמיד רטובה") → סיבות סבירות מדורגות, חומרת המצב (תקין/דורש תשומת לב/דחוף), צעדי טיפול מסודרים, ומה לבדוק בהמשך. תשובה לפי הצמח הספציפי מהמאגר.
4. **תזכורות השקיה והזנה:** לוח זמנים לכל צמח לפי סוג וגורמי הבית, סימון "הושקה/הודשן", התראות (Web Push), תצוגת "מה לעשות היום".
5. **המלצות לפי תנאי הבית:** פרופיל בית (כיווני חלונות, כמות אור, טמפרטורה, לחות, חיות מחמד/ילדים) → התאמה והמלצה למיקום וטיפול לכל צמח.
6. **יומן צמיחה:** ציר זמן תמונות לכל צמח, הערות, והשוואה לפני/אחרי בין אבחונים.
7. **בטיחות:** סימון צמחים רעילים לחתולים/כלבים/ילדים (אזהרה בולטת בכרטיס הצמח ובזיהוי). ציין שזה מידע כללי ולא ייעוץ וטרינרי או רפואי.

## חוויית משתמש ועיצוב
- נווט תחתון בן 4 לשונית: **היום · הג'ונגל · סרוק · פרופיל**.
- מובייל-פירסט, כפתורי מגע גדולים, מצבי טעינה/שגיאה/ריק ברורים בעברית, תמיכה במצב כהה.
- שפה חמה וקצרה. נגישות: ניגודיות, `aria`, ניווט מקלדת.
- היעזר בסקיל `ui-ux-pro-max` לפלטת צבעים וטיפוגרפיה, וב-`rtl-hebrew-docs` לכללי RTL.

## שיטת עבודה
1. הפעל את הסוכן **Plan** לתכנון, והצג תכנית קצרה לפני כתיבת קוד.
2. בנה בשלבים עם commit לכל שלב: שלד ומסד נתונים → זיהוי → מאגר → אבחון → תזכורות → יומן → ליטוש.
3. אחרי כל שלב: הרץ build, lint, בדיקות. הרץ את האפליקציה בפועל (סקיל `run`, Playwright עם Chromium) וצלם מסכים.
4. כתוב בדיקות ליחידות המרכזיות (פרסור תשובת המודל, חישוב תזכורות, ולידציה) ובדיקת אינטגרציה לנתיבי ה-API עם מודל מדומה.
5. בסוף הרץ `security-review` ו-`code-review`. בדוק במיוחד: אין סודות בקוד, הגבלת קצב, הגנה על העלאות, בידוד נתונים בין משתמשים.
6. כתוב `README` בעברית: הרצה מקומית, משתני סביבה, פריסה (Vercel/Fly/Render לשרת, Supabase למסד), ועלות משוערת לשימוש ב-API.

## קריטריוני קבלה
- זיהוי ואבחון עובדים מקצה לקצה מתמונה ומתיאור מילולי, בעברית, עם פלט JSON תקין גם במקרי קצה (תמונה לא של צמח, תמונה מטושטשת).
- הוספה, עריכה ומחיקה של צמח נשמרות בענן ומסתנכרנות בין מכשירים.
- התראת השקיה אמיתית מתקבלת בטלפון אחרי התקנת ה-PWA.
- אין מפתחות בקוד הלקוח. כל הבדיקות והבילד ירוקים. ה-UI כולו RTL ללא אלמנטים שבורים.
